UI parity

Last reviewed: 2026-10-12 · Last updated: 2026-10-18 · Change: minor (shape group Contents row elided; path-editing layer bounds #1220; closed issue references re-audited against upstream/main 470ea7a3) · Target: Adobe After Effects 2026

How closely EffectCraft's interaction matches After Effects: tools, handles, snapping, nudging, modifier keys, shortcuts, drag behaviour, numeric entry, panels, context menus and feel. Evidence is the code at origin/main 1446e27, the 42 scripted UI test files in crates/ui-egui/tests (real pointer and keyboard events, run headless), fidelity/workflow-checks.md and the issue tracker. After Effects was not driven for this pass, so "same as After Effects" means "matches its documentation and users have not reported a difference".

Overall ≈ 65% (estimated): the shape of the interface is After Effects' (menus, panels, workspaces, shortcuts), and the scripted tests cover many interactions, but users keep finding feel and platform differences, and the 26.x interface changes are not in yet.

Path editing (#1220): the Composition viewer suppresses a selected layer’s transform box while using a Pen-family tool on a visible path, or while selecting its vertices with the Selection tool. Path points, Bézier handles and the path’s free-transform controls remain available. Layer transform tools and ordinary layer selection restore the box. Headless ui_viewer tests cover shape paths and masks, corner-vertex dragging and undo, and layers without visible paths.

Estimate

≈ 60–110 h: the open interaction issues above (25–45 h, about 0.2–0.5 h each with a scripted test), 3D gizmos 8–15 h, the 26.x interface changes 10–20 h, an accessibility pass 15–30 h. Checking feel against After Effects needs the owner's Mac with After Effects running; most of the rest parallelises.
